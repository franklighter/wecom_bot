## 系统概述

财富管理系统(WMS)是为金融机构提供的综合财富管理平台,支持客户资产管理、投资组合分析、交易执行和风险评估等核心功能。

**主要模块**:
- 客户管理模块
- 投资组合管理
- 交易执行引擎
- 风险评估系统
- 报表分析系统

## 常见问题与解决方案

### 登录问题

#### 问题 1: 用户无法登录系统,提示"用户名或密码错误"

**关键词**: 登录失败、认证错误、密码错误
**错误代码**: WMS-AUTH-1001

**问题描述**:
用户在登录页面输入凭据后,系统返回"用户名或密码错误"提示,无法进入系统。

**原因分析**:
1. 用户输入的密码确实错误
2. 账户已被锁定(连续失败登录超过5次)
3. 密码已过期(超过90天未更改)
4. 账户被管理员禁用
5. LDAP/AD 认证服务连接异常

**解决方案**:

**步骤 1**: 验证账户状态
```
1. 登录管理后台
2. 进入"用户管理" > "账户查询"
3. 搜索用户账号
4. 查看账户状态字段
```

**步骤 2**: 根据状态处理
- 如果状态为"锁定": 点击"解锁账户"按钮
- 如果状态为"禁用": 联系管理员确认是否需要启用
- 如果状态为"密码过期": 使用"重置密码"功能

**步骤 3**: 检查认证服务
```bash
# 检查 LDAP 连接
telnet ldap-server.company.com 389
# 查看认证服务日志
tail -f /var/log/wms/auth.log
```

**步骤 4**: 重置密码(如需要)
1. 在用户管理界面选择用户
2. 点击"重置密码"
3. 系统生成临时密码并发送至用户邮箱
4. 用户首次登录时需强制修改密码

**预防措施**:
- 建议用户使用密码管理器
- 定期提醒用户更新密码
- 配置合理的账户锁定策略

#### 问题 2: 双因素认证(2FA)验证码无法接收

**关键词**: 2FA、验证码、短信未收到、OTP
**错误代码**: WMS-AUTH-1005

**问题描述**:
用户输入正确的用户名和密码后,系统要求输入双因素认证码,但用户未收到短信或邮件验证码。

**原因分析**:
1. 手机号码或邮箱地址未正确绑定
2. 短信网关服务异常
3. 邮件服务器延迟或故障
4. 用户手机信号问题或邮箱已满
5. 验证码被垃圾邮件过滤

**解决方案**:

**步骤 1**: 验证联系方式
```
1. 在用户管理后台查询用户资料
2. 确认手机号码和邮箱地址是否正确
3. 检查"2FA 启用状态"字段
```

**步骤 2**: 检查服务状态
```bash
# 检查短信网关状态
curl -X GET https://sms-gateway.company.com/health
# 检查邮件队列
mailq | grep -c "^[A-F0-9]"
```

**步骤 3**: 使用备用验证方式
1. 点击"使用其他验证方式"
2. 选择"备用邮箱"或"认证器应用"
3. 或联系 IT 支持临时禁用 2FA

**步骤 4**: 重新发送验证码
1. 等待 60 秒冷却时间
2. 点击"重新发送验证码"
3. 检查垃圾邮件文件夹

**步骤 5**: 更新联系方式(如需要)
1. 使用管理员账户登录
2. 更新用户的手机号码或邮箱
3. 要求用户重新绑定 2FA 设备

**预防措施**:
- 建议用户配置多个验证方式
- 定期测试短信和邮件服务
- 提供认证器应用作为备选方案

### 账户查询问题

#### 问题 3: 客户资产数据显示不完整或为零

**关键词**: 资产查询、数据缺失、余额为零、持仓显示异常
**错误代码**: WMS-DATA-2001

**问题描述**:
用户登录后查看客户资产信息时,发现部分账户余额显示为零,或持仓数据不完整。

**原因分析**:
1. 数据同步延迟(T+1 结算未完成)
2. 数据库查询权限不足
3. 账户状态异常(冻结、休眠)
4. 缓存数据过期未刷新
5. 后台数据同步任务失败

**解决方案**:

**步骤 1**: 检查数据同步状态
```sql
-- 查询最后同步时间
SELECT account_id, last_sync_time, sync_status
FROM account_sync_log
WHERE account_id = 'XXXXXX'
ORDER BY last_sync_time DESC LIMIT 1;
```

**步骤 2**: 手动触发数据刷新
1. 在账户详情页面点击"刷新数据"按钮
2. 等待 30-60 秒让系统重新拉取数据
3. 检查是否显示正常

**步骤 3**: 验证账户状态
```sql
-- 检查账户状态
SELECT account_id, status, freeze_reason
FROM customer_accounts
WHERE account_id = 'XXXXXX';
```

**步骤 4**: 清除缓存
```bash
# 清除 Redis 缓存
redis-cli DEL "account:XXXXXX:balance"
redis-cli DEL "account:XXXXXX:positions"
```

**步骤 5**: 检查同步任务日志
```bash
# 查看同步任务日志
tail -f /var/log/wms/data-sync.log | grep "XXXXXX"
```

**步骤 6**: 重启同步任务(如需要)
```bash
# 重启数据同步服务
systemctl restart wms-data-sync
```

**预防措施**:
- 配置自动数据同步监控告警
- 设置合理的缓存过期时间
- 定期检查数据一致性

#### 问题 4: 交易历史记录查询超时

**关键词**: 查询超时、历史记录、响应慢、数据库超时
**错误代码**: WMS-DATA-2008

**问题描述**:
用户尝试查询客户的交易历史记录时,系统长时间无响应,最终返回"查询超时"错误。

**原因分析**:
1. 查询时间范围过大(超过1年)
2. 数据库索引缺失或失效
3. 历史数据表数据量过大未分区
4. 并发查询过多导致数据库负载高
5. 网络延迟或连接池耗尽

**解决方案**:

**步骤 1**: 缩小查询范围
1. 建议用户将查询时间范围限制在 3 个月内
2. 使用"高级筛选"功能添加更多条件
3. 按交易类型或产品类别筛选

**步骤 2**: 检查数据库性能
```sql
-- 查看慢查询
SHOW PROCESSLIST;
-- 检查表索引
SHOW INDEX FROM transaction_history;
```

**步骤 3**: 优化查询
```sql
-- 添加必要索引
CREATE INDEX idx_trans_date_account
ON transaction_history(account_id, trans_date);
```

**步骤 4**: 使用异步导出
1. 对于大量数据,使用"导出报表"功能
2. 系统后台生成 Excel 文件
3. 完成后通过邮件发送下载链接

**步骤 5**: 检查连接池
```bash
# 查看数据库连接数
mysql -e "SHOW STATUS LIKE 'Threads_connected';"
# 查看最大连接数
mysql -e "SHOW VARIABLES LIKE 'max_connections';"
```

**预防措施**:
- 定期维护数据库索引
- 实施历史数据归档策略
- 配置查询超时限制
- 使用读写分离架构

### 交易执行问题

#### 问题 5: 交易订单提交失败,提示"风控拒绝"

**关键词**: 交易失败、风控、订单被拒、限额超限
**错误代码**: WMS-TRADE-3001

**问题描述**:
用户尝试提交交易订单时,系统返回"交易被风控系统拒绝"的错误提示。

**原因分析**:
1. 超出客户单日交易限额
2. 触发异常交易监控规则
3. 客户风险等级不匹配产品风险
4. 账户可用资金不足
5. 产品交易时间限制

**解决方案**:

**步骤 1**: 查看风控拒绝原因
```sql
-- 查询风控日志
SELECT * FROM risk_control_log
WHERE order_id = 'XXXXXX'
ORDER BY create_time DESC LIMIT 1;
```

**步骤 2**: 检查交易限额
1. 登录风控管理后台
2. 查询客户的交易限额配置
3. 确认当日已使用额度

**步骤 3**: 验证客户风险等级
```sql
-- 查询客户风险评级
SELECT customer_id, risk_level, assessment_date
FROM customer_risk_profile
WHERE customer_id = 'XXXXXX';
```

**步骤 4**: 调整限额或申请豁免
1. 如需提高限额,提交审批流程
2. 填写"交易限额调整申请表"
3. 需要客户经理和风控部门双重审批

**步骤 5**: 检查产品适配性
1. 确认产品风险等级
2. 验证客户是否完成风险评估
3. 检查产品交易时间窗口

**预防措施**:
- 定期更新客户风险评估
- 提前告知客户交易限额
- 配置合理的风控规则阈值

用户提交交易订单后,订单状态一直显示"处理中",超过正常处理时间仍未完成。

```bash
# 查看消息队列积压情况
rabbitmqctl list_queues name messages
```

**步骤 3**: 查看第三方接口日志
```bash
# 检查交易网关日志
tail -f /var/log/wms/trade-gateway.log | grep "XXXXXX"
```

#### 问题 7: 批量交易导入失败

**关键词**: 批量导入、Excel 导入、文件格式错误、导入失败
**错误代码**: WMS-TRADE-3010

**问题描述**:
用户使用批量交易功能上传 Excel 文件后,系统提示"文件格式错误"或部分订单导入失败。

**原因分析**:
1. Excel 文件格式不符合模板要求
2. 必填字段缺失或格式错误
3. 文件编码问题(非 UTF-8)
4. 文件大小超过限制(>10MB)
5. 包含特殊字符或公式

**解决方案**:

**步骤 1**: 下载最新模板
1. 在批量交易页面点击"下载模板"
2. 确保使用最新版本模板(v2.3)
3. 不要修改模板的列标题和顺序

**步骤 2**: 验证文件格式
- 文件格式: .xlsx (不支持 .xls)
- 编码: UTF-8
- 最大行数: 1000 行
- 文件大小: < 10MB

**步骤 3**: 检查数据格式
```
- 账户号码: 10 位数字
- 交易金额: 数字,最多 2 位小数
- 交易日期: YYYY-MM-DD 格式
- 产品代码: 6 位字母数字组合
```

**步骤 4**: 查看导入日志
1. 点击"查看导入历史"
2. 找到失败的导入记录
3. 下载"错误明细报告"
4. 根据错误提示修正数据

**步骤 5**: 分批导入
1. 如果数据量大,分成多个文件
2. 每个文件不超过 500 行
3. 逐批导入并验证结果

**预防措施**:
- 提供数据格式验证工具
- 在模板中添加数据验证规则
- 提供详细的导入指南文档

### 报表生成问题

#### 问题 8: 月度报表生成失败或数据不准确

**关键词**: 报表生成、数据错误、统计不准、月报失败
**错误代码**: WMS-REPORT-4001

**问题描述**:
用户尝试生成客户月度资产报表时,系统提示生成失败,或生成的报表数据与实际不符。

**原因分析**:
1. 报表生成任务超时
2. 数据源不一致(多个数据库)
3. 计算逻辑错误或配置错误
4. 临时表空间不足
5. 并发生成报表过多

**解决方案**:

**步骤 1**: 检查报表任务状态
```sql
-- 查询报表生成任务
SELECT task_id, status, error_message
FROM report_tasks
WHERE report_type = 'MONTHLY' AND customer_id = 'XXXXXX'
ORDER BY create_time DESC LIMIT 1;
```

**步骤 2**: 验证数据源
```sql
-- 对比不同数据源的数据
SELECT SUM(balance) FROM account_balance WHERE customer_id = 'XXXXXX';
SELECT SUM(balance) FROM account_balance_replica WHERE customer_id = 'XXXXXX';
```

**步骤 3**: 重新生成报表
1. 在报表管理页面找到失败的任务
2. 点击"重新生成"按钮
3. 选择"强制刷新数据源"选项

**步骤 4**: 检查临时空间
```bash
# 检查磁盘空间
df -h /tmp
# 清理临时文件
find /tmp/wms_reports -mtime +7 -delete
```

**步骤 5**: 手动计算验证
1. 使用 SQL 手动计算关键指标
2. 与报表数据对比
3. 如有差异,提交 Bug 报告

**预防措施**:
- 配置报表生成队列限制
- 定期清理临时文件
- 实施报表数据质量检查

```sql
SELECT * FROM mysql.slow_log
```

#### 问题 11: 系统在交易高峰期频繁超时

**关键词**: 高并发、超时、峰值、系统崩溃
**错误代码**: WMS-PERF-5005

**问题描述**:
在交易高峰期(如开盘时段),系统频繁出现超时错误,部分用户无法访问。

**原因分析**:
1. 并发连接数超过系统限制
2. 数据库连接池耗尽
3. 消息队列积压严重
4. 负载均衡配置不当
5. 未实施限流措施

**解决方案**:

#### 问题 12: 定时任务执行失败或重复执行

**关键词**: 定时任务、Cron、任务失败、重复执行

**问题描述**:
系统的定时任务(如日终结算、数据同步)未按时执行,或出现重复执行的情况。

**原因分析**:
1. Cron 表达式配置错误
2. 任务执行时间过长导致重叠
3. 分布式环境下缺少锁机制
4. 任务调度器服务异常
5. 服务器时间不同步

**解决方案**:

**步骤 1**: 检查任务调度状态

```bash
# 查看 Cron 任务

```

**步骤 2**: 验证 Cron 表达式
```python
# 使用在线工具验证
# https://crontab.guru/
# 或使用 Python 验证
from croniter import croniter
croniter.is_valid('0 2 * * *')
```

**步骤 3**: 添加分布式锁
```python
# 使用 Redis 实现分布式锁
import redis
r = redis.Redis()
lock = r.lock('task:daily_settlement', timeout=3600)
if lock.acquire(blocking=False):
    try:
        # 执行任务
        pass
    finally:
        lock.release()
```

**步骤 4**: 检查服务器时间
```bash
# 查看系统时间
date
# 同步时间
ntpdate ntp.aliyun.com
```

**步骤 5**: 手动执行任务
```bash

```

**预防措施**:
- 配置任务执行监控
- 实施任务幂等性设计
- 使用专业任务调度系统(如 Airflow)
- 定期检查任务执行日志

#### 问题 13: 用户会话频繁过期需要重新登录

**关键词**: 会话过期、频繁登录、Session 失效、Token 过期
**错误代码**: WMS-AUTH-1010

**问题描述**:
用户在使用系统过程中,经常被强制退出需要重新登录,即使操作间隔很短。

**原因分析**:
1. Session 超时时间设置过短
2. 多服务器环境下 Session 未共享
3. 浏览器 Cookie 被清除
4. 负载均衡未启用会话保持
5. Redis Session 存储异常

**解决方案**:

**步骤 1**: 调整 Session 超时时间
```python
# 修改配置文件
SESSION_TIMEOUT = 7200  # 2 小时
SESSION_REFRESH = True  # 启用自动刷新
```

**步骤 2**: 配置 Session 共享
```python
# 使用 Redis 存储 Session
SESSION_TYPE = 'redis'
SESSION_REDIS = redis.from_url('redis://localhost:6379/0')
```

**步骤 3**: 检查负载均衡配置
```nginx
# 启用会话保持
upstream wms_backend {
    ip_hash;  # 或使用 sticky cookie
    server 192.168.1.10:8080;
    server 192.168.1.11:8080;
}
```

**步骤 4**: 验证 Cookie 设置
```javascript
// 检查 Cookie 属性
document.cookie
// 确保设置了正确的 Domain 和 Path
```

**步骤 5**: 检查 Redis 状态
```bash
# 查看 Redis 内存使用
redis-cli INFO memory
# 检查 Session 数据
redis-cli KEYS "session:*" | wc -l
```

**预防措施**:
- 实施 Token 自动续期机制
- 提供"记住我"功能
- 配置合理的超时时间
- 监控 Session 存储健康状态

## FAQ 常见问答

**Q1: 如何重置用户密码?**
A: 管理员可在"用户管理"模块选择用户,点击"重置密码",系统将生成临时密码并发送至用户邮箱。用户首次登录时需强制修改密码。

**Q2: 客户资产数据多久更新一次?**
A: 实时数据每 5 分钟更新一次,日终数据在 T+1 日凌晨 2 点完成结算后更新。可手动点击"刷新"按钮立即拉取最新数据。

**Q3: 交易订单可以撤销吗?**
A: 订单状态为"待审核"或"处理中"时可以撤销,已完成或已成交的订单无法撤销。撤销操作需要相应权限。

**Q4: 报表生成需要多长时间?**
A: 简单报表(如日报)通常 1-2 分钟,复杂报表(如年度报表)可能需要 10-30 分钟。大型报表建议使用异步生成功能。

**Q5: 系统支持哪些浏览器?**
A: 推荐使用 Chrome 90+、Firefox 88+、Edge 90+。不支持 IE 浏览器。建议使用最新版本浏览器以获得最佳体验。

**Q6: 如何提高系统访问速度?**
A: 1) 使用有线网络而非 WiFi; 2) 清除浏览器缓存; 3) 关闭不必要的浏览器标签页; 4) 避免在交易高峰期进行大量查询操作。

**Q7: 批量交易最多可以导入多少条记录?**
A: 单次最多支持 1000 条记录。如需导入更多,请分批进行。建议每批 500 条以获得更好的处理速度。

**Q8: 文件上传有什么限制?**
A: 单个文件最大 50MB,支持格式: PDF、DOC、DOCX、XLS、XLSX、JPG、PNG。不支持可执行文件和压缩包。

**Q9: 如何导出大量历史数据?**
A: 对于超过 5 万条的数据,建议使用"异步导出"功能。系统将在后台生成文件,完成后通过邮件发送下载链接。

**Q10: 系统维护时间是什么时候?**
A: 定期维护时间为每周日凌晨 2:00-4:00。紧急维护会提前 24 小时通过系统公告通知用户。

**Q11: 如何联系技术支持?**
A: 工作时间(9:00-18:00)可拨打热线 400-XXX-XXXX,或发送邮件至 support@company.com。紧急问题请使用系统内的"在线客服"功能。

**Q12: 数据安全如何保障?**
A: 系统采用银行级加密传输(TLS 1.3),数据库加密存储,定期备份。所有操作都有审计日志记录。通过 ISO 27001 信息安全认证。
